# Environment checks

Use the verified project profile. Check mode visibility, skill activation,
documentation lookup and runtime query as separate outcomes in a fresh Bob task.
Preserve other modes, skills, MCP servers and runtime settings.

If documentation access fails, capture the exact failure and use applicable
official documentation for work it covers. Do not claim an unrelated search
proves the dedicated documentation connection works.

If CLI and MCP disagree, compare the target, executable/version and operation
arguments before changing either. Never print full environment files to diagnose.
Local deployment can use remote inference; record the actual processing location.

Container availability, successful initialization and real extraction are
different checks. A completed initialization job may exit successfully while a
long-running service restarts. Interpret its role, exit code and restart trend.
Treat historical vendor workarounds as dated observations, not default setup.
